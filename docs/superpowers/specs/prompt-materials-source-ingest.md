prompt1:
在账号设定里加一个「来源」板块，登记本机知识库文件夹和项目文件夹。路径是这台机器上的绝对路径，不监听文件、不自动扫。一个账号下同一路径不能挂两遍。关掉就不参与提炼，删来源不删已经入库的卡片。
核心:弹药在本机，先挂上才谈提炼

prompt2:
点扫描不要直接灌进素材库。抽成短卡片，作者过目、改文案、改类型、去掉勾选，再点入库。知识库按路径和标签分亲历还是引用，不要让模型猜「这是不是我的经历」。McKinsey那种一篇拆多张卡，一张一个论断，禁止把整篇笔记塞进一张卡。
核心:素材库是签字后的事实层，不是知识库镜像

prompt3:
项目要作者自己标类别：验证中 / 已交付 / 仓里有产品文档。验证中的先起草一份成果说明（做成了什么、验证的是哪句话、学到了什么，必须写明这是demo不是产品），作者改完确认之前不许抽卡。有产品文档的只读那一份文档，不要拿.ts当素材。成果说明只存在产品里，不写回仓库。
核心:项目类别是作者的判断，未确认是硬闸

prompt4:
素材库加一类「引用」。写作只召回已经入库的卡片，不现搜原文。亲历最多4条、引用最多2条，一边不够名额不匀给另一边。用到引用必须点名出处，不许写成「我调研发现」或第一人称经历。选题那一步仍然不召回。检查那一步也要看引用有没有点名出处。
核心:引用不是二等亲历，少给是为了不挤掉「我做了什么」

prompt5:
入库时每张卡一个匿名勾选，亲历默认开、引用默认关。勾了的把公司名人名换成类别描述（温氏→一家农牧企业），数字和机制不动。重扫不覆盖作者改过的卡，只追加标题还没出现过的。路径填错就在来源上标红，不要连环弹窗，已有素材不动。
核心:过目一次、改过就认；客户真名在入库时处理完
